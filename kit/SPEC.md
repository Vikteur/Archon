# Copilot kit: layout and contract

This file is the contract shared by every piece of kit work:
- the generator `scripts/kit-sync.ts`;
- the embedder `scripts/generate-bundled-kit.ts`;
- the CLI commands `archon kit add` and `archon kit doctor`;
- the hand-written overlays.

Change it only together with every consumer.

## Purpose

`archon kit add <project>` installs a GitHub Copilot CLI version of an agent setup into a project. The setup comes from a source repo that uses Claude Code (wedding-portal: `.claude/`, `.archon/`, `scripts/`, `docs/scaffold-templates/`).

- **Source of truth.** The source repo stays the source. `kit/profiles/**` is **generated**, so never hand-edit it.
- **Hand-written parts.** Only `kit/overlays/**`, `kit/SPEC.md` and `kit/kit.defaults.yaml` are written by hand.

## Folders

```
kit/
  SPEC.md                    this file (hand-written)
  kit.defaults.yaml          the default project config, written to <project>/.archon/kit.yaml (hand-written)
  overlays/<profile>/        hand-written files that replace or add generated files
    overlay.json             { "<target path>": { "derivedFrom": "<source path>|null", "sourceSha256": "<hex>|null" } }
    <target path>...         the file contents, at their target path
  profiles/<profile>/        GENERATED by kit-sync: files at their path in the target project
    <target path>...
  manifest.json              GENERATED by kit-sync
```

## Profiles

Profiles are installed in this order. When two profiles carry the same path, the later one wins.

| Profile | Requires | Content |
|---|---|---|
| `core` | — | The Archon run tooling: delegator, STOP policy, merge, CI by SHA, retro and run observability scripts. Also: hooks, generic skills and agents, the codegraph MCP entry, the tool installer, the githooks, `.github/copilot-instructions.md` and the instructions templates. |
| `java` | core | Shared Java/JVM skills, the layer rules (as `.github/instructions`), ArchUnit/PIT/Gradle CI scripts, `scripts/scaffold*`, the stack-neutral scaffold templates, and the analyst, developer, test-writer and debugger agents. |
| `java-quarkus` | java | The Quarkus originals: bean-config-di, persistence-repository, resilience4j, exception-to-http, api-first-controller, testcontainers, the Quarkus-flavoured scaffold templates, and run-wedding-portal → `run-app`. |
| `java-spring` | java | The same paths as `java-quarkus`, rewritten for Spring Boot. It comes from `kit/overlays/java-spring/`, which kit-sync copies to `profiles/java-spring/`. |
| `openapi-contract` | core | The contract-api MCP server (`scripts/portal-mcp/**`), `scripts/contract-agent-readiness/**`, contract-pin, contract-db-parity and the contract-agent. |

`java-quarkus` and `java-spring` are mutually exclusive. The default for a new project is `core,java,java-spring,openapi-contract`.

## manifest.json

```json
{
  "version": 1,
  "source": { "name": "wedding-portal", "commit": "<sha>" },
  "profiles": {
    "core": { "requires": [], "description": "..." },
    "java": { "requires": ["core"], "description": "..." }
  },
  "exclusive": [["java-quarkus", "java-spring"]],
  "files": [
    {
      "path": ".github/agents/reviewer.agent.md",
      "profile": "core",
      "mode": "0644",
      "template": false,
      "origin": ".claude/agents/reviewer.md",
      "kind": "agent",
      "sha256": "<hex of the file in profiles/>"
    }
  ],
  "aliases": {
    "@scout-copilot": { "provider": "copilot", "model": "claude-haiku-5.5" },
    "@build-copilot": { "provider": "copilot", "model": "claude-sonnet-5.5" },
    "@analyse-copilot": { "provider": "copilot", "model": "claude-opus-5.5" }
  },
  "postInstall": [
    { "profile": "core", "run": "bash scripts/install-hooks.sh", "optional": true },
    { "profile": "core", "run": "bash .archon/scripts/codegraph-setup.sh", "optional": true },
    { "profile": "openapi-contract", "run": "npm ci --prefix scripts/portal-mcp", "optional": false },
    { "profile": "openapi-contract", "run": "bash .archon/scripts/portal-mcp-setup.sh", "optional": true },
    { "profile": "core", "run": "bash .archon/scripts/mcp-setup.sh", "optional": true }
  ]
}
```

- `files` is sorted by `profile` order, then by `path`. Paths use forward slashes and never contain `..`.
- `kind` is one of `agent`, `skill`, `hook`, `instructions`, `mcp`, `workflow`, `script`, `template`, `config` or `doc`.
- `mode` is `0755` for files that are executable in the source (git mode 100755) and `0644` for everything else.

## Placeholders (`template: true`)

- **Syntax.** A placeholder is `@@KIT_<NAME>@@`, where NAME is an UPPER_SNAKE key of `.archon/kit.yaml`; nested keys are joined with `_`. Examples: `@@KIT_BASE_BRANCH@@` and `@@KIT_CONTRACT_REPO@@`.
- **Rendering.** `archon kit add` renders placeholders at install time.
- **Lists.** A list value renders as its items joined with `, `.
- **Missing keys.** A missing key renders empty, and `kit add` warns about it.
- **No overlap.** The syntax never clashes with mustache `{{ }}` or shell `${ }`.
- **Prefer runtime reads.** A script that can read `.archon/kit.yaml` at runtime should do that, using yq with a default. Use placeholders only where a file can't read config: skill or agent markdown, and JSON hook or MCP files.

## .archon/kit.yaml (project config, from kit.defaults.yaml)

```yaml
profiles: [core, java, java-spring, openapi-contract]
base_branch: main
gh_accounts: []              # gh-switch-account skill
ntfy_topic: ""               # notify-owner.sh
agent_cli: copilot           # supervisor/delegator scripts: claude | copilot
build_workflow: build-feature-copilot
java_version: 21
framework_packages: ["org.springframework.."]   # arch-fitness: forbidden in domain
modules:                     # layer globs, used by the .github/instructions applyTo fields and the scope rules
  domain: "**/*-domain/**"
  usecase: "**/*-usecase/**"
  adapter: "**/*-adapter/**"
  gateway: "**/*-gateway/**"
  platform: "**/platform/**"
generated_globs: ["**/build/generated/**"]
commands:
  test: "./gradlew test"
  integration_test: "./gradlew integrationTest"
  check: "./gradlew check"
contract:
  server_name: contract-api
  repo: ""                   # owner/repo of the contract hub
  spec_path: contract/dist/openapi.yaml
  tag_key: contractTag       # gradle.properties key that pins the contract
  generated_dir: ""          # e.g. shared-adapter/build/generated/openapi/src/main/java/com/acme/api
  api_package: ""            # e.g. com.acme.api
```

## Conversion rules (kit-sync)

| Source | Target | Rule |
|---|---|---|
| `.claude/agents/<n>.md` | `.github/agents/<n>.agent.md` | Frontmatter becomes `name`, `description`, `model`, `tools`, `mcp-servers` and `include-custom-instructions: true`. The model maps opus→`claude-opus-5.5`, sonnet→`claude-sonnet-5.5`, haiku→`claude-haiku-5.5`. Tools map Read/Grep/Glob→`read`+`search`, Edit/Write/MultiEdit/NotebookEdit→`edit`, any `Bash(...)`→`execute`, WebFetch/WebSearch→`web`, `Agent(...)`→`agent`, `mcp__<s>__*`→`<s>/*`, `mcp__<s>__<t>`→`<s>/<t>`, and drops Skill (skills load by name), PushNotification, SendMessage and ListAgents. The `skills:` list becomes a body line `Load these skills first: a, b.`. Each Claude-only tool that is dropped becomes a body note under `## On Copilot CLI`. |
| `.claude/skills/<n>/**` | `.github/skills/<n>/**` | Copied verbatim. In SKILL.md frontmatter it keeps `name`, `description`, `license` and `allowed-tools`, and drops the rest. A dropped `disallowed-tools` or `disable-model-invocation` is added as a body note under `## On Copilot CLI`. |
| `.agents/skills/archon-cli/**` | the same path | Verbatim. |
| `.claude/settings.json` `hooks` | `.github/hooks/kit.json` | `{"version":1,"hooks":{<event>:[{"type":"command","bash":"bash .github/hooks/dispatch.sh <ClaudeEvent> '<matcher>' <script path> <args>","timeoutSec":N}]}}`. Events map SessionStart→sessionStart, UserPromptSubmit→userPromptSubmitted, PreToolUse→preToolUse, PostToolUse→postToolUse, PostToolUseFailure→postToolUseFailure, SubagentStart→subagentStart, SubagentStop→subagentStop, SessionEnd→sessionEnd, Stop→agentStop. |
| — | `.github/hooks/dispatch.sh` | Generated, a fixed script. It reads stdin, normalizes the payload with `.claude/hooks/scripts/payload.sh`, applies the Claude matcher regex to the normalized tool name, runs the script with the normalized payload, and translates a Claude `hookSpecificOutput.permissionDecision` into Copilot's top-level `permissionDecision`/`permissionDecisionReason`. |
| `.claude/settings.json` `permissions.deny` | `.archon/copilot/deny.json` | Read by `run-guard.sh`, which enforces it in every session, not only in run worktrees. |
| `.claude/rules/<layer>.md` | `.github/instructions/<layer>.instructions.md` | `paths:` becomes `applyTo:`, a comma-joined glob string built from the `@@KIT_MODULES_<LAYER>@@` placeholder when the layer is in `modules`, otherwise the verbatim globs. |
| MCP servers | `.github/mcp.json` | `codegraph` is `codegraph serve --mcp` with env `CODEGRAPH_MCP_TOOLS=explore,node,search,callers,callees,impact` (core). `@@KIT_CONTRACT_SERVER_NAME@@` is `node scripts/portal-mcp/server.mjs` (openapi-contract). Because JSON can't be split by profile, kit-sync writes the full core+contract file to `openapi-contract` and a core-only one to `core`. |
| `.archon/workflows/build-feature.yaml` | `.archon/workflows/build-feature-copilot.yaml` (core) | The rewrites of `.archon/scripts/copilot-workflow.js`. Both workflows ship. |
| Other files on the copy lists | the same path | Verbatim. Each one is assigned to a profile by the copy lists in `scripts/kit-sync.ts`. |

## What never ships

- `run-wedding-portal`, which becomes the stack's `run-app`.
- The project's own `docs/code-maps/*.md` leaves. Only the README and the `kind: worked-example` leaves ship.
- `docs/memory.md`, `docs/rewrite/**`, `backlog/**`, `contract/**`, the build output, secrets and `.env` files.
